# โปรแกรมตรวจ Notes สำหรับ BO ad — แบบก่อนพัฒนา

วันที่ 19 ตุลาคม 2569 · สถานะ: รอเจ้าของงานยืนยันแบบ

## ผลที่ผู้ใช้ต้องการ

โปรแกรม Windows แยกจากเว็บไซต์ เปิดด้วยไฟล์ .exe ใช้ตรวจ Notes ใน LINE โดยเฉพาะ เลื่อนอ่านย้อนหลังและเก็บข้อมูลอัตโนมัติ แสดงรายละเอียดทั้งหมดพร้อมวันที่ก่อนบันทึกเข้าระบบ และส่งออก Excel ก่อนนำเข้า BO ad ได้ เป้าหมายคือเชื่อมหลักฐานการใช้ SN ใน Notes เข้ากับประวัติจ่ายสินค้าและงานในเว็บไซต์ โดยไม่ต้องให้ช่างกรอกข้อมูลย้อนหลังใหม่ทั้งหมด

คำว่า “บันทึกอัตโนมัติ” ในแบบนี้หมายถึงเก็บฉบับร่างในเครื่องทันทีที่อ่านได้ ส่วนการส่งเข้าระบบจริงเป็นอีกขั้นหลังตรวจและยืนยัน ข้อนี้เป็นการตีความของผู้พัฒนาเพื่อให้สอดคล้องกับคำขอให้เห็นสรุปและ Excel ก่อนนำเข้า

## รูปแบบโปรแกรมที่เสนอ

ชื่อใช้งาน **BO Notes Inspector** สำหรับ Windows 10/11 x64 แจกเป็น ZIP แบบพกพา มี BO-Notes-Inspector.exe พร้อมไฟล์ OCR ที่จำเป็น แตก ZIP แล้วเปิดใช้งาน ไม่ต้องติดตั้ง Python หรือ Node.js ไม่รับรองว่าเป็นไฟล์เดียว เพราะโมเดลภาษาและไลบรารีอ่านภาพอาจต้องอยู่ข้างโปรแกรม

ผู้พัฒนาเลือกใช้ C#/.NET และ WPF พร้อม runtime ในชุดส่งมอบ ใช้ OCR ในเครื่องรองรับไทยและอังกฤษเป็นหลัก เช่น Tesseract พร้อมโมเดล tha/eng ไม่ส่งภาพหรือข้อความไปบริการ AI ภายนอก เลือกรุ่นไลบรารีและรายละเอียดแพ็กเกจในขั้นวางแผน ปัจจุบันเครื่องนี้มี .NET runtime แต่ยังไม่มี SDK จึงต้องเตรียมเครื่องมือ build หลังยืนยันแบบ

ไม่ยึด LINE Bot และไม่อ่านรหัสผ่าน/คุกกี้/ฐานข้อมูลส่วนตัวของ LINE ไม่เรียก private API หรือถอดการเข้ารหัส โปรแกรมอ่านเฉพาะหน้าต่างและกลุ่มที่ผู้ใช้เลือกและเปิดให้ดู

## ขั้นตอนใช้งาน

1. ผู้ใช้เปิด LINE PC เข้าสู่ระบบเอง และเปิด Notes ของกลุ่มที่ต้องการ
2. โปรแกรมให้เลือกหน้าต่าง LINE และยืนยันชื่อกลุ่ม/บริเวณรายการ Notes จากภาพตัวอย่าง ไม่ค้นหรืออ่านแชตอื่นเอง
3. ตั้งขอบเขตการเก็บ: จำนวนหน้าหรือรายการสูงสุด ระยะเวลาสูงสุด และตัวกรองประเภทงาน/วันที่ในเนื้อหางาน เลือกอ่านหน้าปัจจุบันหรือเลื่อนลงย้อนหลังจากตำแหน่งที่เปิดไว้ ไม่อ้างว่าเริ่มที่รายการใหม่สุดถ้าผู้ใช้เปิดไว้กลางรายการ
4. กด “เริ่มอ่าน” โปรแกรมอ่านภาพ กดขยายข้อความเมื่อพบปุ่มที่ระบุได้แน่ชัด เลื่อนแบบมีภาพทับซ้อน เก็บภาพต้นฉบับและผลอ่านทุกช่วง บันทึกฉบับร่างลงเครื่องอัตโนมัติ
5. กดหยุด/พักได้ทันที มีปุ่มหยุดและปุ่มลัด Escape เก็บสิ่งที่อ่านสำเร็จแล้ว เมื่อกลับมาทำต่อจะตรวจหน้าต่าง/กลุ่มใหม่ก่อน ไม่เลื่อนต่อด้วยพิกัดเก่า
6. หน้า “ตรวจรายการ” แสดงภาพต้นฉบับคู่กับข้อความและข้อมูลแยกช่อง แก้ข้อความ เลือกช่าง ยืนยันวันที่ และติ๊กเลือกรายการที่จะส่งออก/นำเข้าได้
7. หน้า “สรุปก่อนนำเข้า” แสดงจำนวนตามประเภท/วัน/ช่าง SN ที่อ่านได้ รายการซ้ำ ช่องว่าง ข้อขัดแย้ง และสิ่งที่ยังไม่ยืนยัน
8. ส่งออก Excel ของชุดที่เลือกก่อนนำเข้า ทุกครั้งที่เปลี่ยนข้อความ ช่าง หรือชุดรายการหลังส่งออก ต้องส่งออกใหม่เพื่อให้รายงานตรงกับข้อมูลที่จะส่ง
9. เข้าสู่ BO ad ด้วยบัญชีที่มีสิทธิ์ แล้วกดยืนยันนำเข้าเฉพาะรายการที่ผ่านการตรวจ โปรแกรมแสดงผลสำเร็จ/ซ้ำ/ขัดแย้ง/ล้มเหลวรายรายการและหมายเลขอ้างอิงใน BO ad

การยืนยันนำเข้าในโปรแกรมนี้สร้างรายการรอตรวจในเมนู LINE ของ BO ad เท่านั้น ไม่เรียกคำสั่งตัด SN หรือเปลี่ยนสถานะงานเป็น completed การรับรองใช้สินค้า/ปิดงานยังเป็นขั้นตอนเดิมของ BO ad และไม่ข้ามข้อกำหนดรูปหลักฐานหรือค่าจ้าง

## หน้าจอ

- **อ่าน Notes:** หน้าต่าง/กลุ่มที่เลือก ภาพบริเวณอ่าน ปุ่มเริ่ม/พัก/หยุด ขอบเขตจำนวน/เวลา ตัวนับภาพและงาน สถานะการอ่าน และเหตุผลที่หยุด
- **ตรวจรายการ:** ตารางเลือกหลายรายการ กรองช่วงวันและ 4 ประเภท แสดงต้นฉบับข้างรายละเอียด ช่างเจ้าของงาน ช่องซ้ำ และ SN พร้อมสถานะ “ยังไม่ยืนยัน/ยืนยันแล้ว/ต้องตรวจ/ข้อมูลไม่ครบ/ซ้ำ”
- **สรุปและ Excel:** ยอดรวมตามวัน/ประเภท/ช่าง รายการผิดปกติ ปุ่มส่งออกและหลักฐานประกอบ แสดงรุ่นข้อมูลล่าสุดที่ส่งออกแล้ว
- **นำเข้าและประวัติ:** ปลายทาง BO ad บัญชีที่ใช้ รายการที่จะส่ง คำยืนยันก่อนส่ง ผลนำเข้าทีละรายการ และประวัติลองใหม่

ชื่อปุ่มและข้อความใช้งานเป็นภาษาไทย รายละเอียดเทคนิคอยู่หน้าตั้งค่าหรือประวัติข้อผิดพลาดเท่านั้น

“รายละเอียดทั้งหมด” ที่เสนอสำหรับรุ่นแรกคือข้อความทุกช่องในโพสต์ รวมช่องที่ไม่รู้จัก/ช่องซ้ำ และภาพหน้าจอเป็นหลักฐาน ไม่รวมการเปิดดาวน์โหลดรูปหรือวิดีโอแนบทุกไฟล์และอ่านรายละเอียดภายในรูปแนบ หากเจ้าของงานต้องการส่วนนี้ต้องขยายแบบก่อนพัฒนา ไม่ถือว่าอนุมัติไว้แล้ว

## การอ่าน Notes และข้อจำกัดที่ต้องแสดงตรงไปตรงมา

จากการทดลอง LINE PC เปิดหน้าต่าง Notes และขยายข้อความได้ แต่ accessibility tree ไม่ให้ข้อความในโพสต์ และการลากเลือก/เมนูที่ทดลองยังคัดลอกข้อความไม่ได้ จึงยังไม่มีหลักฐานว่า OCR อ่าน SN จาก Notes จริงได้แม่นพอหรือเก็บหลายโพสต์ได้ครบ การพัฒนาต้องเริ่มจากทดสอบการอ่านจริงก่อน หากไม่ผ่านต้องแสดงข้อจำกัด ไม่ส่งมอบปุ่มที่แกล้งทำสำเร็จ

จุดตรวจความเป็นไปได้ก่อนทำโปรแกรมเต็ม: อ่าน Notes จริงต่อเนื่องอย่างน้อย 5 โพสต์จากกลุ่มที่ผู้ใช้เปิด ตรวจด้วยคนว่าภาพและข้อความแต่ละโพสต์จับคู่ถูก ไม่มีการรวมข้ามโพสต์ และไม่มีรายการที่มองเห็นในช่วงนั้นหายโดยไม่แจ้ง ทดสอบข้อความยาว/See more เพิ่มด้วยข้อมูลจำลองหากตัวอย่างจริงไม่มี ทุกตัวอักษรใน SN ที่ OCR ผิดหรือไม่แน่ใจต้องถูกแก้/ยืนยันก่อนนำเข้า และรายงานจำนวนช่องที่ต้องแก้จริง ยังไม่กำหนดเปอร์เซ็นต์ความแม่นที่ไม่ได้วัด หากผ่านแค่การอ่านภาพแต่เลื่อน/แบ่งโพสต์ยังไม่น่าเชื่อถือ ถือว่ายังไม่ผ่านตัวเก็บอัตโนมัติ ต้องรายงานผลและขอปรับแนวทางก่อน ไม่ลดเหลือคัดภาพเองแล้วอ้างว่าเสร็จตามคำขอ

การอ่านเป็น state machine แบบจำกัดขอบเขต: ตรวจหน้าต่าง/ชื่อกลุ่มและภาพ → อ่าน → ขยายเฉพาะปุ่มที่ยืนยันได้ → เก็บภาพ/ข้อความ → เลื่อน → ตรวจความคืบหน้า ไม่กดปุ่มส่ง โพสต์ แชร์ แก้ไข หรือลบใน LINE

หยุดเมื่อหน้าต่างหาย/ย่อ/ถูกบังจนอ่านไม่ได้ กลุ่มเปลี่ยน พบหน้าเข้าสู่ระบบหรือกล่องโต้ตอบที่ไม่รู้จัก อ่านภาพไม่ได้ หรือชนเพดานจำนวน/เวลา หากภาพไม่เปลี่ยนซ้ำหลังลองเลื่อนอย่างจำกัด ให้หยุดพร้อมเหตุผล “ไม่พบความคืบหน้า” ไม่ถือเป็นหลักฐานว่าครบทุก Notes

ข้อความยาวเกินจอใช้การอ่านภาพต่อเนื่องที่มีส่วนทับซ้อน ประกอบได้เมื่อมีหลักฐานตรงกัน หากขอบเขตระหว่างสองโพสต์กำกวม ให้เก็บเป็นชิ้นส่วนรอตรวจ ห้ามรวมข้ามโพสต์หรือเดาเนื้อหาที่หาย ต้องอ่านหัวข้อจนถึงจุดจบที่เห็นและไม่มี “See more” ค้าง ก่อนให้สถานะพร้อมตรวจ

ไม่ใช้วันของรายการหนึ่งเป็นเหตุหยุดอ่านย้อนหลัง เพราะ Notes อาจไม่เรียงตามวันที่ติดตั้ง ค่าช่วงวันที่กรองตามวันทำงานในเนื้อหา หลังอ่านแล้วเท่านั้น ชิ้นที่ยังไม่รู้วันอยู่ในกลุ่ม “ไม่ทราบวันที่” และไม่ถูกทิ้งเงียบ ๆ

รุ่นแรกเป็นการเก็บแบบมีคนเริ่มรันใน session ที่เปิดและปลดล็อก ไม่ใช่ service เบื้องหลัง 24 ชั่วโมง ผู้ใช้สามารถอ่านแล้วพักและกลับมาทำต่อ มีประวัติว่ารอบไหนเริ่มจากตำแหน่งใด พบวันงานช่วงใด และหยุดเพราะอะไร ไม่รับประกัน Notes ที่ถูกลบหรือบัญชีไม่มีสิทธิ์เปิด

## รูปแบบข้อมูลและการตรวจ

รองรับ #ปิดงานติดตั้งais, #ปิดงานติดตั้ง3bb, #ปิดงานเปลี่ยนอุปกรณ์3bb และ #งานMA พร้อมกลุ่ม “ไม่รู้ประเภท” เก็บทุกรายการที่อ่านได้ ไม่ทิ้งเพราะตัวอ่านไม่รู้รูปแบบ

รักษาข้อความ OCR ดิบ ภาพต้นฉบับ ข้อความที่ผู้ใช้แก้ และประวัติแก้แยกกัน แยกช่องตามลำดับและชื่อเดิม เก็บหัวข้อซ้ำหลายครั้ง ไม่รวมให้ข้อมูลหาย เก็บเลขเคส/Order/SRT/SN เป็นข้อความ ไม่เดา O/0 หรือ I/1 และไม่แทนด้วย SN ใกล้เคียงในฐานโดยอัตโนมัติ

วันที่แยกชัดเจน:
- วันที่ติดตั้ง/แก้ไข: ข้อความเดิมและค่ามาตรฐานสำหรับกรอง รองรับ พ.ศ. สั้น เช่น 19/10/69 = 2026-10-19
- วันที่โพสต์ Notes: เก็บเมื่อมองเห็น ถ้ามีแต่ “3 hours ago” ให้เก็บข้อความนั้นพร้อมเวลาอ่าน ไม่แต่งเป็นเวลาจริงที่แน่นอน
- วันที่อ่านและนำเข้า: เวลาเหตุการณ์ของโปรแกรม แสดงเขตเวลาไทย

ชื่อผู้โพสต์เป็นหลักฐานประกอบ ไม่ใช่ LINE user ID และไม่ใช้เลือกช่างอัตโนมัติจากชื่อที่คล้ายกัน ผู้ดูแลต้องเลือกช่างจริงต่อรายการหรือกำหนดหลายรายการพร้อมกันแล้วตรวจอีกครั้ง ค่าที่อ่านไม่ชัด/ช่องสำคัญขาด/ข้อความไม่ครบ ห้ามนำเข้าได้จนแก้และยืนยัน

SN ทุกตัวที่ได้จากภาพต้องผ่านการตรวจของคนก่อนส่งเข้าระบบ การตรงกับสินค้าในฐานเพียงอย่างเดียวไม่ยืนยันว่า OCR อ่านถูก SN เก่าในงาน MA แยกจาก SN ใหม่และไม่ถูกเสนอหัก

คีย์กันซ้ำในเครื่องอิงกลุ่ม ชื่อผู้โพสต์ ข้อความที่ normalize แบบรักษาเลขและเครื่องหมาย และรหัสงานเมื่อมี พร้อมภาพอ้างอิง หากไม่แน่ใจว่าเป็นภาพทับซ้อนของโพสต์เดียวหรือคนละโพสต์ ให้เสนอรายการซ้ำให้คนตรวจ ห้ามลบข้อมูลอัตโนมัติ รุ่นที่ข้อความเปลี่ยนเก็บเป็นอีกเวอร์ชัน

## การจัดเก็บและ Excel

บันทึกข้อมูลใน LocalAppData ของผู้ใช้ แยกโฟลเดอร์แต่ละชุด มีฐานข้อมูลฉบับร่างและ images พร้อม journal บันทึกหลังแต่ละขั้นที่สำเร็จ ใช้งานอ่าน/ตรวจ/ส่งออกได้แม้ไม่มีอินเทอร์เน็ต ไม่เก็บในโฟลเดอร์ติดตั้งโปรแกรมและไม่ขึ้น cloud เอง

Excel แยกแผ่น สรุป / ติดตั้ง AIS / ติดตั้ง 3BB / เปลี่ยนอุปกรณ์ 3BB / งาน MA / ไม่รู้ประเภท / ตรวจ SN / ต้นฉบับและแหล่งที่มา / ผลนำเข้า

แผ่นประเภทใช้หัวคอลัมน์และลำดับตามข้อความ LINE เก็บชื่อซ้ำเป็นคอลัมน์ซ้ำ วันที่แสดงตามต้นฉบับ ส่วนวันที่มาตรฐานและ metadata อยู่แผ่นสรุป/แหล่งที่มา ทุกเลขยาวเป็น text และค่า = + - @ ไม่ทำงานเป็นสูตร ช่องว่างยังว่าง ข้อความเกินขนาดเซลล์แบ่งส่วนโดยไม่ตัดทิ้ง

ส่งออก Excel ได้แม้รายการยังไม่ผ่านตรวจ แต่แสดงสถานะให้ชัด แผ่นผลนำเข้าก่อนส่งจริงเป็น “ยังไม่นำเข้า” ส่งออกใหม่หลังนำเข้าได้เพื่อเก็บผลจริง แต่ไม่แก้ไฟล์เก่าที่ผู้ใช้ดาวน์โหลดไว้เงียบ ๆ

มีตัวเลือก ZIP หลักฐานประกอบ รวม Excel, manifest รุ่นข้อมูล และเฉพาะภาพที่อ้างอิงในรายการที่เลือก ใช้ชื่อไฟล์และเส้นทางสัมพัทธ์ ไม่อ้าง path ส่วนตัวของเครื่องอื่นเป็นหลักฐานถาวร

## เชื่อม BO ad

ปลายทางตั้งต้น https://bonusais.com ใช้ HTTPS เท่านั้น ไม่เชื่อม MySQL โดยตรง ไม่ใช้ LINE secret และไม่ฝังบัญชี/กุญแจใน .exe ผู้ใช้กรอกบัญชี BO ad เองเมื่อจะนำเข้า เก็บ access token ในหน่วยความจำเท่านั้นรุ่นแรก ไม่เก็บรหัสผ่าน ไม่อ่าน session Chrome

ใช้สิทธิ์ admin/super_admin ตาม API เดิม โหลดรายชื่อช่างที่ approved และตรวจข้อความผ่าน parser ฝั่ง server ก่อนยืนยัน ไม่เชื่อผลตรวจจาก desktop เพียงอย่างเดียว

ขยายช่องทางนำเข้าเดิมแบบเพิ่มได้ ไม่เปลี่ยนความหมายการนำเข้าเก่า: รับ client batch ID/item ID, revision, source=notes_desktop และ metadata แหล่งที่มา พร้อมเก็บความสัมพันธ์กับ line_records และ audit บน server การส่งครั้งแรกต้องจบเป็น review เสมอ แม้ระบบเปิด auto mode อยู่

ไม่อัปโหลดภาพทั้งหมดอัตโนมัติรุ่นแรก หลักฐานภาพอยู่ในเครื่องและ ZIP ส่งออก ส่วน server เก็บข้อความต้นฉบับ/ข้อความรับรอง ชื่อกลุ่ม/ผู้โพสต์/วันที่ที่เห็น เวลาอ่าน hash ภาพ หมายเลขชุด และผู้ยืนยัน เพื่อย้อนกลับมาชุดหลักฐานได้ ภาพที่ hash อ้างอิงต้องอยู่ในชุดที่บันทึกสำเร็จจริง

ส่งเป็นรายรายการหรือชุดย่อยที่มีผลรายรายการชัดเจน จำกัดขนาดตาม API server ถ้าเน็ตขาดหลังส่ง ใช้รหัสนำเข้าเดิมตรวจผล/ลองใหม่โดยไม่สร้างซ้ำ ถ้าข้อความต่างแต่เลขงานเดิมให้รอตรวจ conflict ไม่เขียนทับ รุ่นแรกนำเข้าเฉพาะข้อความและ metadata ไม่สั่ง confirm/report_only/ปิดงาน/ตัดสินค้า

การ deploy backend ที่เพิ่มต้องแยกจากการทดสอบ .exe ใช้ฐานจำลองก่อน ไม่เขียนข้อมูลช่างจริงเพื่อทดสอบ และตรวจการเปลี่ยนแปลงล่าสุดของ BO ad ก่อน commit/push

## การตรวจรับและสิ่งส่งมอบ

- ทดสอบอ่านหน้าต่าง LINE จริงอย่างน้อยหนึ่งชุดที่เจ้าของงานเลือก แสดงภาพคู่ข้อความและผลแยกครบ ตรวจ SN ทุกตัวโดยคน รายงานอัตราอ่านได้/ต้องแก้จากชุดทดสอบจริง ไม่กล่าวอ้างครบทั้งกลุ่มจากจำนวนหน้าที่อ่านสำเร็จ
- ทดสอบโพสต์ยาวหลายภาพ ขอบโพสต์ ภาพทับซ้อน ขยายไม่สำเร็จ วันหาย ช่องซ้ำ อ่านเลขกำกวม หยุดกลางทางและเปิดกลับ รวมทั้งไม่มีความคืบหน้า/หน้าต่างเปลี่ยน
- ทดสอบ 4 ตัวอย่างผู้ใช้จากข้อความที่ทราบผล เป็นการทดสอบ parser แยกจากความแม่น OCR
- ตรวจไฟล์ Excel กลับด้วยตัวอ่านอื่นว่าหัวข้อซ้ำ/เลขยาว/วันที่/สถานะ/จำนวนแถวครบ ส่งออกได้ก่อนล็อกอิน และแก้ข้อมูลแล้วต้องส่งออกใหม่ก่อนนำเข้า
- ทดสอบ API กับฐานแยก: สิทธิ์/ช่าง approved/นำเข้าซ้ำ/เครือข่ายขาดหลัง commit/ข้อความเปลี่ยน/ไม่มีผลต่อ inventory หรืองาน completed
- เปิด .exe จาก ZIP ที่ส่งมอบบนเครื่องนี้ โดยไม่อาศัย SDK หรือ Node/Python และแจ้งข้อจำกัดที่พบจริง
- ส่งมอบ ZIP โปรแกรมพร้อม .exe, ZIP ซอร์สและคำสั่ง build, คู่มือไทย, ผลทดสอบ และ Excel ตัวอย่างที่ระบุว่าเป็นข้อมูลจำลอง

## สิ่งที่ไม่รวมในรุ่นแรก

ไม่อ่านมือถือ/ทุกกลุ่มเอง ไม่ทำงานขณะเครื่องล็อกหรือ LINE ปิด ไม่ข้ามการล็อกอิน ไม่กู้ Notes ที่ลบ ไม่อ้างว่าหมายเลข SN ที่ OCR ตรงฐานยืนยันความถูกต้องได้ ไม่ปิดงานหรือตัดสต็อกอัตโนมัติจากการอ่านภาพ และไม่เขียนกลับหรือแก้ Notes ใน LINE

## จุดที่ขอยืนยันก่อนพัฒนา

ยืนยันขั้นตอน **อ่านและเก็บร่างอัตโนมัติ → ตรวจรายละเอียด/วันที่/ช่าง/SN → ส่งออก Excel → ยืนยันนำเข้าเป็นรายการรอตรวจใน BO ad** โดยการตัดสินค้าและปิดงานยังรับรองใน BO ad ตามเดิม และรับทราบว่าชุด .exe อาจมีโฟลเดอร์ OCR ประกอบใน ZIP เดียวกัน

ขอบเขตที่ต้องให้เจ้าของงานเลือกพร้อมการยืนยัน: เริ่มจากข้อความทุกช่องพร้อมภาพหน้าจอหลักฐานตามแบบนี้ หรือรวมการเปิดอ่านและเก็บรูปแนบภายใน Notes ด้วย
