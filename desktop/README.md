# BO Notes Inspector

โปรแกรม Windows สำหรับอ่าน Notes จากหน้าต่าง LINE ที่เลือก เก็บร่างในเครื่อง ตรวจข้อความ/วันที่/ช่าง/SN ส่งออก Excel แล้วนำเข้า BO ad เป็นรายการรอตรวจ ไม่ตัดสินค้าจากการอ่านภาพ

รุ่น 1.0.0 สำหรับ Windows x64: แตก ZIP ทั้งโฟลเดอร์แล้วเปิด `BO-Notes-Inspector.exe` ต้องเก็บ DLL และโฟลเดอร์ tessdata ไว้ด้วย ไม่ต้องติดตั้ง Python/Node/.NET SDK โปรแกรมยังไม่ได้ลงนามผู้เผยแพร่ หาก Windows มีคำเตือนให้ตรวจสอบไฟล์และตัดสินใจด้วยตัวเอง

โปรแกรมรวม .NET runtime แล้ว ส่วน native OCR อาจต้องใช้ Microsoft Visual C++ Redistributable x64 บนเครื่องอื่น (เครื่องพัฒนามีอยู่แล้ว จึงยังไม่ยืนยันเครื่องใหม่ที่ไม่มี runtime นี้) หากเริ่มอ่านแล้วโหลด native DLL ไม่ได้ ให้ติดตั้งจาก Microsoft อย่างเป็นทางการ: https://learn.microsoft.com/cpp/windows/latest-supported-vc-redist

## หลักการใช้งาน

เปิด LINE และเข้าระบบเอง เปิด Notes กลุ่มที่ต้องการ ใช้หน้าต่างที่ไม่ถูกบังและปลดล็อกเครื่อง เลือกหน้าต่างในโปรแกรมแล้วเริ่มอ่าน กด Escape หรือปุ่มหยุดเพื่อยุติ โปรแกรมไม่ส่งข้อความ/แชร์/แก้/ลบ Notes

1. แท็บ **อ่าน Notes**: เลือกหน้าต่าง Notes (ขนาดและรหัสแสดงเพื่อแยกจากหน้าต่างแชต) ระบุชื่อกลุ่มตามหน้าจอ ตั้งจำนวนหน้ากับเวลา เริ่มจากตำแหน่งที่ต้องการตรวจย้อนหลัง เปิดอ่านได้ครั้งละไม่เกิน 500 หน้าจอ/7200 วินาที ตัวกรองวันใช้กับรายการที่อ่านแล้ว ไม่ทำให้ข้าม Notes โดยอัตโนมัติ
2. แท็บ **ตรวจรายการ**: เลือกวันที่ทำงานและประเภท รายการไม่ทราบวันยังแสดงเพื่อตรวจ ชุดเริ่มต้นไม่เลือกรายการใด กดเลือกเฉพาะที่แสดงแล้วตรวจทีละรายการ แก้ข้อความ/แท็กประเภทให้ตรงภาพ ขยายภาพเพื่อเทียบทุกช่องและ SN ขีดครบสี่ช่องยืนยันด้วยตัวเอง
3. เชื่อมบัญชี admin/super_admin ของ BO ad ที่แท็บ **เชื่อม BO ad** เพื่อโหลดรายชื่อช่าง ชื่อผู้เขียน LINE เป็นเพียงข้อมูลแสดง ไม่ผูกกระเป๋าจากชื่ออัตโนมัติ เลือกช่างเจ้าของแต่ละงานหรือกำหนดให้รายการที่เลือกหลังตรวจแล้ว
4. แท็บ **สรุปและ Excel**: ตรวจวัน ช่าง จำนวน SN และทุกตัวกรองก่อนส่งออก Excel/ZIP เก็บหลักฐาน เลือกรายการได้รวมทุกตัวกรอง; รายการที่ซ่อนยังถูกเลือกอยู่ได้ ดูยอดรวมในสรุปเสมอ ข้อความยาวถูกแบ่งส่วนโดยเก็บต้นฉบับครบ
5. ปุ่ม **ตรวจชุดข้อมูลและยืนยันนำเข้า** จะตรวจภาพ/ธงยืนยัน/ช่าง/เลขงานซ้ำและ Excel รุ่นปัจจุบันก่อนแสดงสรุปยืนยัน เว็บไซต์ตรวจข้อความอีกครั้ง หากข้อมูลเปลี่ยนหลังส่งออกต้องส่งออกใหม่ นำเข้าเป็น review/conflict เท่านั้น จากนั้นเปิดเมนู LINE ของ BO ad เพื่อตรวจ SN กับกระเป๋าและยืนยันตามขั้นตอนเดิม

หากเน็ตหลุดหลังเว็บไซต์รับข้อมูล ให้ใช้ฉบับร่างและรุ่นเดิมกดซ้ำ ระบบคืนใบรับเดิม ข้อมูลแก้ไขสร้างรุ่นใหม่; อาจเข้าคิว conflict เพื่อให้แอดมินตัดสินใจ ผลนำเข้าบันทึกในร่างและส่งออก Excel อีกครั้งเพื่อเก็บประวัติได้ ไม่มีการปิดงาน/หักสินค้าโดยโปรแกรมนี้

ร่างบันทึกอัตโนมัติระหว่างอ่านและทุก 5 วินาทีหลังแก้ไข ใช้ **เปิดโฟลเดอร์ชุดนี้** เพื่อหา `draft.json` แล้วเปิดด้วย **เปิดฉบับร่าง** หลังปิดโปรแกรม มี snapshot สำรอง `draft.json.bak` เผื่อไฟล์หลักเสียหาย ออกจากบัญชีเมื่อเสร็จ ไม่มีการบันทึกรหัสผ่านหรือ token ลงร่าง

OCR อาจอ่านชื่อภาษาไทย หัวข้อ และ SN ผิด แม้ข้อความดูคล้ายต้นฉบับ ต้องตรวจเทียบภาพทั้งหมด รวมเลข 0/O และ 1/I ทุก SN ก่อนนำเข้า ข้อความที่ระบบระบุว่าเห็นขอบเขตครบยังไม่ใช่ข้อความที่รับรองแล้ว

บันทึกไว้ใน `%LOCALAPPDATA%/BO Notes Inspector` ไม่ส่งภาพไป OCR ภายนอกหรือ BO ad โดยอัตโนมัติ ไฟล์ในโฟลเดอร์นี้อาจมีข้อมูลลูกค้าและช่าง ผู้ใช้ควรเก็บชุดหลักฐานควบคู่รายงานที่นำเข้า

## ข้อจำกัดที่วัดได้ระหว่างทดสอบ

- หน้าต่าง Notes ของ LINE ไม่ส่งข้อความโพสต์ผ่าน accessibility tree จึงใช้ OCR ในเครื่อง
- Tesseract อ่านหัวข้อ/ชื่อ/SN บางตัวผิดจริง เช่น a/i/s หรือ E/S จึงไม่มีการยืนยัน SN อัตโนมัติ
- เก็บภาพจาก 24 viewport พร้อมภาพก่อน/หลังขยายข้อความ ตัวต่อภาพรักษาทั้งรายการและชิ้นส่วนที่กำกวม ไม่อ้างว่านับเป็นจำนวนงานที่ไม่ซ้ำทั้งหมด
- ใช้การจับคู่พิกเซลของส่วนที่ทับซ้อนเพื่อเชื่อมข้อความที่ถูกเลื่อน ไม่ใช้ SN ใกล้เคียงเดาว่าเป็นงานเดียวกัน
- รูปแนบอาจมีตัวหนังสือที่ OCR เห็นด้วย ต้องดูภาพและแก้ข้อความก่อนรับรอง รุ่นแรกไม่เปิดดาวน์โหลด/อ่านไฟล์แนบทีละไฟล์
- อ่านถึงเพดานจำนวนภาพ/เวลา หรือหยุดเพราะภาพไม่คืบหน้า ไม่เท่ากับยืนยันว่าเก็บ Notes ทั้งกลุ่มครบแล้ว

## สร้างโปรแกรม

สำหรับผู้พัฒนา รัน `./desktop/build.ps1 -OutputDirectory C:/path/to/outputs` ใน PowerShell สคริปต์ดาวน์โหลด SDK และ OCR ที่ตรึงรุ่น/ตรวจ hash ลงใน .build-tools, ทดสอบและ publish self-contained win-x64 ไฟล์ OCR ต้องอยู่ใน tessdata ข้าง .exe และ native DLL ต้องมากับชุด publish ใช้ lock files ของ NuGet ร่วมกับซอร์ส

Backend: deploy `backend/line/desktop.js`, `desktop-migration.sql` และ router/service/migrate รุ่นเดียวกัน แล้วรัน `node line/migrate.js` จาก backend หลังสำรองฐานข้อมูล เป็นตารางเพิ่มโดยไม่เปลี่ยนโหมดตัดสินค้าเดิม API ใช้ token ของ BO ad และ middleware admin เดิม ห้ามเปิด endpoint โดยไม่ตรวจสิทธิ์
