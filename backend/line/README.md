# เมนูนำเข้าข้อมูล LINE สำหรับ BO ad

เมนู `/line-import` ใช้สิทธิ์ admin/super_admin รับข้อมูล 4 ประเภท จัดเก็บต้นฉบับ ตรวจงาน/SN และบันทึกการใช้จากกระเป๋าช่างหรือทีม พร้อม Excel 7 แผ่นงาน

## สถานะการติดตั้ง
โค้ดและ migration พร้อมตรวจทดสอบแยก ไม่มีการรัน migration บนฐานข้อมูลจริง ยังไม่ได้เชื่อม OA BOT หรือ Sheets receiver จริง
การเห็นหน้าเว็บตัวอย่างไม่ได้หมายความว่าเชื่อมบัญชี LINE แล้ว

## ติดตั้งบน BO ad
1. สำรองฐานข้อมูลและ source ปัจจุบัน ติดตั้งไฟล์เปลี่ยนแปลงและใช้ dependencies เดิม (Node 20+; ทดสอบ Node24/MariaDB10.4.32)
2. ตั้งค่าฐานข้อมูลเดิมผ่าน server environment ตามระบบ BO ห้ามใส่ credentials ลง Git
3. รัน `node backend/line/migrate.js` จากโฟลเดอร์ BO โดยตรวจว่า target DB ถูกต้องก่อน คำสั่งนี้ใช้ config/env และ config/db เดิม ไม่เรียก server.js ไม่เปิด cron
4. ตรวจว่า inventory_logs.id, job_used_inventory.id, ma_job_used_inventory.id เป็น AUTO_INCREMENT ถ้ายังไม่เป็น runner จะหยุด ให้ผู้ดูแลฐานข้อมูลแก้ชนิดคอลัมน์ตามระบบเดิมก่อน ห้ามใช้ MAX(id)+1 เมื่อรับข้อความพร้อมกัน
5. เพิ่มตัวแปรจาก .env.line.example ลง environment จริง กำหนด LINE_CHANNEL_SECRET ของ OA BOT เท่านั้น และ LINE_IMPORT_WORKER_ENABLED=true แล้ว restart API ขณะนี้โหมดหักใน line_settings ยังปิดอยู่
6. Build frontend ด้วย `cd frontend` แล้ว `npm run build` และนำ dist ที่ build จาก checkout ซึ่งรวมงานแก้ค้างของผู้ใช้ไปยัง hosting ตามวิธีเดิม ห้ามนำ dist เก่าจากฐานทดสอบทับงานขาย
7. LINE Developers ของ BOT: Webhook URL `https://bonusais.com/api/line/webhook` (หรือ /line/webhook เมื่อ Passenger ตัด /api); Verify; เปิด Use webhook และ Webhook redelivery; เปิด Allow bot to join group chats แล้วเชิญ BOT เข้ากลุ่มงาน
8. ให้ช่างส่งข้อความปิดงานตัวอย่าง กลุ่ม/ผู้ส่งที่พบจะอยู่หน้าตั้งค่า ผูก source ID กับทีม และ LINE user ID กับบัญชีช่างที่ตรวจตัวตนแล้ว
9. ผูกสินค้าแต่ละชนิดกับบทบาท ONU / Playbox / Mesh / SIM / Camera ให้ตรงคลังเดิม มิฉะนั้นจะเข้ารอตรวจ ไม่เดาชนิดสินค้า
10. ตรวจผลในโหมดตรวจอย่างเดียวก่อน จึงเปิดตัดอัตโนมัติในหน้าเมนู ข้อความก่อนผูกบัญชี/กลุ่มและไฟล์เก่าจะไม่ถูกตัดย้อนหลังเอง

ไม่ต้องใช้ Channel access token สำหรับรับข้อความตัวอักษร ระบบนี้ไม่ส่ง reply/push เข้า LINE และไม่ดึง profile อัตโนมัติ จึงลดการจัดเก็บข้อมูลรับรองที่ไม่จำเป็น

## ข้อความย้อนหลังและ LINE Notes
Messaging API ไม่มี API อ่านเนื้อหา Notes หรือประวัติเก่าทั้งกลุ่ม ให้นำเข้าข้อความโดยวางหรือใช้ TXT แล้วเลือกช่าง ตรวจตัวอย่าง และยืนยันแต่ละงาน
รองรับไม่เกิน 1 MB และ 100 งานต่อการนำเข้าหนึ่งครั้ง แบ่งไฟล์หากเกิน ไม่อ่านรูปหรือ PDF เป็น SN
ชื่อผู้ส่งใน TXT เป็นข้อมูลประกอบ ไม่ถือเป็นหลักฐานระบุบัญชี LINE

## การตัดและแก้รายการ
- ช่างผู้ส่งต้องผูกบัญชี กลุ่มได้รับอนุญาต ทีม/งานตรง และทุก SN ผ่านการตรวจ จึงหักครบในธุรกรรมเดียว
- SN เก่า ของ MA ไม่หักและไม่รับคืนเอง; สาย/วัสดุไม่มี SN ไม่หักจากระยะสายโดยการเดารุ่น
- SN งานเดิมใช้แล้วเชื่อมประวัติเดิมไม่หักซ้ำ ทั้งจาก LINE และจากหน้าปิดงานเดิม
- ข้อความเปลี่ยนเป็นรุ่นขัดแย้ง ให้ผู้ดูแลตรวจและเลือก “รับข้อมูลรุ่นนี้” อย่างชัดเจน
- หาก SN เปลี่ยนหลังหักแล้ว ต้องคืน/เปลี่ยนผ่านระบบเดิมก่อน ไม่แก้สต็อกจากการแก้ข้อความ
- ข้อความที่ยังไม่ตัดสามารถแก้ข้อความ/ช่างเป็นรุ่นใหม่ พร้อม audit และตรวจอีกครั้ง
- เมื่อแอดมินคืนอุปกรณ์ผ่านการแก้จบงานเดิม จะยกเลิกผลนำเข้าที่เกี่ยวข้อง การส่งข้อความเก่าซ้ำไม่หักกลับเอง
- การนำเข้าไม่ปิดสถานะงาน ไม่แทนรูป MA และไม่ลงค่าแรง/น้ำมัน/ค่าแรกเข้า

## Excel
ดาวน์โหลดตามตัวกรองวันเริ่มและสิ้นสุดรวมทั้งสองวัน แยก 4 ประเภท + สรุป + ประวัติอุปกรณ์ + ข้อความต้นฉบับ
หัวคอลัมน์ใช้คำในต้นฉบับรวมคำผิดและตัวพิมพ์ต่างกัน หัวข้อซ้ำเป็นคอลัมน์ซ้ำตามลำดับ ค่าทุกช่องเป็นข้อความ
ค่าเกิน 30,000 ตัวอักษรแสดงส่วนแรกพร้อม note ในแผ่นประเภท และเก็บข้อความเต็มต่อเป็นหลายแถวในแผ่นต้นฉบับ
ค่าเริ่มต้นรายงานเฉพาะรายการรับรองแล้ว เลือกรวมรอตรวจได้ ไม่รวมรุ่นก่อนหน้าเป็นผลงานซ้ำ จำกัด 10,000 งานต่อไฟล์ให้ลดช่วงวันที่หากเกิน

## Google Sheets (รายงานหลังบันทึก)
ใช้ spreadsheet ID ที่ผู้ใช้ให้ไว้ ไม่มีการให้ client เลือกปลายทางอื่น
1. สร้าง Apps Script แยกสำหรับ receiver และวาง sheets-report.gs
2. Script Properties: SPREADSHEET_ID ตาม .env.line.example และ SYNC_SECRET สุ่มยาวอย่างน้อย32bytes เก็บตรงกับ LINE_SHEETS_SECRET เฉพาะฝั่งเซิร์ฟเวอร์ ไม่ใส่ในหน้าเว็บหรือแชต
3. Deploy Web App ทำงานเป็นเจ้าของชีตและรับ HTTPS POST ได้ การอนุญาต OAuth/สิทธิ์เข้าถึงนี้ต้องให้เจ้าของบัญชีตรวจและยืนยัน
4. ใส่ deployment /exec URL ใน LINE_SHEETS_URL แล้ว restart API
5. receiver ตรวจ HMAC และเวลา ป้องกัน replay เก่า และคุมเลขรุ่นก่อน upsert; sheet tabs ใช้ prefix LINE ไม่ทับ Sheet1/Jobs เดิม
6. ส่งออกผ่าน outbox หลังธุรกรรมสต็อกสำเร็จ ปลายทางล้มเหลว retry โดยไม่หักสต็อกอีก ไม่มีการ rollback สต็อกจาก Sheets
7. แผ่นประเภทเก็บข้อมูลรับรอง แผ่น LINE_ข้อความต้นฉบับ เก็บแต่ละรุ่นครบแบบแบ่งส่วน แผ่นสรุปและประวัติแสดงสถานะที่เปลี่ยนแล้ว

## ตรวจทดสอบและดูตัวอย่างเฉพาะเครื่อง
- ฐานทดสอบต้องเป็น MariaDB แยกบน 127.0.0.1:3318 ไม่ใช้ DB จริง; lineFixture.js บังคับ port และชื่อ bo_line_test_PID
- `node --test backend/tests/*.test.js` ทดสอบ parser, MySQL transaction, HTTP signature/role/filter, completion office/MA, return, Sheets outbox และ source column mapping
- `node --test frontend/src/utils/*.test.mjs` และ `npm run build` จาก frontend
- local preview: LINE_PREVIEW=true แล้วรัน backend/tests/linePreviewServer.js; frontend VITE_API_URL=http://127.0.0.1:4319/api, Vite port5190
- บัญชีทดสอบเฉพาะ preview: line-demo / line-demo (ใช้กับบัญชีจริงไม่ได้)
- ข้อมูลใน preview เป็นข้อมูลจำลอง และ preview API ไม่ใช่ production server

## ย้อนการติดตั้ง
หยุด worker และปิดโหมดอัตโนมัติก่อนถอด source อย่าลบตาราง LINE หรือประวัติสินค้าเพื่อย้อนโปรแกรม
รายการที่ใช้จริงต้องคืนผ่านระบบคลัง/แก้จบงานที่มี audit ไม่แก้จำนวนใน SQL เพื่อให้ยอดดูเหมือนก่อนติดตั้ง
